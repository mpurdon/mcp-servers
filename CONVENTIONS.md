# MCP Server Conventions

Every server in this monorepo is standardized to the same shape, derived from
the `mongodb` reference package. New servers and ports MUST follow these rules
so they behave identically across **Claude Desktop**, **Claude Cowork**, and
**Claude Code**.

## 1. Runtime & module system

- **TypeScript, ESM, `NodeNext`.** Extend `@mpurdon/tsconfig` (`tools/tsconfig/base.json`).
- Import sibling modules with explicit `.js` extensions (`./config.js`), because output is ESM.
- Target Node `>=20`. Use only stable Node APIs.
- Single runtime dependency floor: `@modelcontextprotocol/sdk` + `zod`. Add per-server clients (`mongodb`, `mysql2`, etc.) as needed.

## 2. Transport

- **stdio only** for v1. Wire `StdioServerTransport` in `src/index.ts`. No HTTP/Docker variants.
- The process is spawned per-session by the host (Desktop / Cowork / Code). It must speak JSON-RPC on stdout and nothing else.

## 3. Logging — never pollute stdout

- **All diagnostics go to `stderr`** via `process.stderr.write(...)`. Writing logs to stdout corrupts the JSON-RPC stream.
- Prefix every line with the server name: `[mongodb] ...`.
- ESLint forbids bare `console.log`; only `console.warn` / `console.error` are allowed.

## 4. Configuration

Two sanctioned config styles — pick the one that fits the secret shape:

- **Env vars** (simple key/token servers, e.g. `freshbooks`, `github`, `milo`): read from `process.env`, document every key in `.env.example`. Validate with zod at startup.
- **JSON config file** (multi-environment servers, e.g. `mongodb`): read `~/.<name>-mcp/config.json`, validate with a strict zod schema, `chmod 600`.

In both cases:

- Validate config at startup. On failure, throw a `ConfigError` whose message tells the user exactly how to fix it (which var/file, sample contents), write it to stderr, and `process.exit(1)`.
- **Never commit real credentials.** `.env` is gitignored; only `.env.example` is tracked.

## 5. Secrets never cross the wire

- Tool responses must never echo credentials, full connection strings, tokens, or auth headers.
- When a host/identity is useful to return, surface a sanitized form only (see `safeHostFromUri` in `mongodb/src/config.ts`).

## 6. Input validation

- Every tool's parameters are defined and validated with **zod** before any external call.
- Reject unknown fields (`.strict()`) on config objects.

## 7. Destructive-operation gates

- Mutating tools that are dangerous (drops, mass deletes, prod writes) require an explicit `confirmed: true` argument.
- When called without confirmation, return a structured `confirmationRequired` payload describing exactly what would run, rather than executing. Re-invocation with `confirmed: true` performs it. (See `mongodb/src/tools/write.ts`.)

## 8. Process lifecycle & resilience

- Handle `SIGINT` and `SIGTERM`: close clients/connections, then `process.exit(0)`.
- Guard `unhandledRejection` so a late-resolving external call can't crash the process and reset session state.
- `main().catch(...)` writes a fatal line to stderr and exits non-zero.

## 9. Package layout

```
packages/<name>/
  src/
    index.ts          # shebang, load+validate config, wire tools + stdio transport, lifecycle
    config.ts         # zod schema + loader + ConfigError + sanitizers
    connection.ts     # external client lifecycle (omit for stateless servers)
    tools/            # one file per tool group; each exports register<Group>Tools(server, deps)
  package.json        # @mpurdon/mcp-<name>, bin { "<name>": "dist/index.js" }, files: ["dist"]
  tsconfig.json       # extends ../../tools/tsconfig/base.json
  eslint.config.js    # re-exports @mpurdon/eslint-config
  README.md           # what it does, config keys, tool reference, install snippet
  .env.example        # for env-var servers
  CHANGELOG.md        # generated by Changesets
```

## 10. Package.json contract

- Name: `@mpurdon/mcp-<name>`. Bin: `{ "<name>": "dist/index.js" }` (no redundant `-mcp` suffix).
- `"type": "module"`, `"main": "dist/index.js"`, `"files": ["dist"]`, `"publishConfig": { "access": "public" }`.
- Scripts: `build` (`tsc`), `dev` (`tsx src/index.ts`), `typecheck` (`tsc --noEmit`), `lint` (`eslint .`).
- `engines.node >= 20`.
- `src/index.ts` starts with `#!/usr/bin/env node` so the built `dist/index.js` is directly executable as the bin.

## 11. Host integration

All three hosts use the same `mcpServers` config schema:
`{ "<name>": { "command", "args", "env" } }`. The published bin means the canonical
registration is:

```json
{ "command": "npx", "args": ["-y", "@mpurdon/mcp-<name>"], "env": {} }
```

The `@mpurdon/mcp-servers` CLI (`npx @mpurdon/mcp-servers configure`) writes this
into the right config file per host:

- **Claude Desktop:** `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) / `%APPDATA%\Claude\claude_desktop_config.json` (Windows)
- **Claude Code:** `~/.claude.json` (user scope) or a project `.mcp.json`
- **Claude Cowork:** per-workspace `.mcp.json`
